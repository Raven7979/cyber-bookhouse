# 能力与依赖边界

`cyber-bookhouse` 必须能在没有其他私人 Skill 的电脑上独立说明并执行自己的流程。
第三方软件不放进压缩包，但检查、调用顺序、失败降级和验收规则都放在包内。

## 包内自带

- 安装状态与入口测试记录；
- 内容平台的分级处理规则；
- 普通公开网页正文读取脚本；
- X 公开帖子和 X Article 匿名采集脚本，包含正文身份校验、原图下载和明确失败回执；
- YouTube 公开元数据和字幕采集脚本；
- 本地音视频探测、代表帧和本地转写调用脚本；
- 当前模型、图片输入、Browser/CDP 和视频处理的验收规则；
- 标准笔记、蒸馏笔记和详细拆解规则；
- 基于真实结构生成本地 SVG / HTML 流程图、分支图、框架图和时间线；
- Obsidian 笔记格式、证据边界和可见性验收；
- 飞书入口、微信助理入口和飞书文档的配置规则。

## 依赖宿主 Agent

- 操作用户明确授权的可见浏览器页面；
- 读取 PDF、Word、PPT 和图片中的可见内容；
- 通过一张真实图片证明当前模型/入口具备视觉能力；
- 根据真实证据写摘要、校对文本和组织 Markdown。

宿主没有相应能力时，必须直接说明缺失，并让用户提供官方导出或本地文件。
不能假设另一套 Skill 已经安装。

## 外部软件

运行下面的检查，不要凭文件名猜是否可用：

```bash
<python-command> "<skill-dir>/scripts/dependency_doctor.py"
```

按任务只处理对应的缺项。下载地址统一读取
[software-links.md](software-links.md)。不得把安装程序、账号 Cookie、Token
或用户浏览器配置放进 `cyber-bookhouse.zip`。

图片和视频处理还要读取 [runtime-models.md](runtime-models.md)。视频号要读取
[wechat-channels.md](wechat-channels.md)。`dependency_doctor.py` 只能报告本机
文件和工具状态，不能替用户批准 Browser/CDP，也不能证明腾讯元宝已登录或
某条真实视频能下载。

## 支持等级

- `direct`：包内有明确脚本或稳定公开接口，并经过真实样本验收。
- `host`：需要 Codex / Claude / WorkBuddy 的可见浏览器或文档能力。
- `file`：需要用户提供本地媒体、字幕或官方导出。
- `metadata`：只能可靠保留标题、作者、链接和限制。

对外说“支持平台”时，同时说明支持等级。不要把 `metadata` 说成完整正文、
视频或逐字稿支持。

## 系统支持

- macOS：`stable`，安装向导和核心路线已完成真机测试。
- Windows 10 / 11：`beta`，路径、检测和脚本已适配，必须按
  [windows.md](windows.md) 在当前电脑做完桌面、手机和 Obsidian 真实测试。
- Linux：本版不提供自动安装向导，不宣称完整支持。

## 发布前空白机器验收

1. 解压包后，所有 `SKILL.md` 引用的脚本和参考文件都存在。
2. 不安装其他私人 Skill，也能运行依赖检查、普通网页、X、YouTube
   和本地媒体脚本；视频号自动下载缺少独立组件时必须如实降级为本地文件。
3. 缺少外部软件时，输出 `dependency_missing` 和官方来源，不编造成功。
4. YouTube 遇到真人验证时，输出 `authorization_required`，不反复重试。
5. 用户提供可见字幕文本后，脚本能生成可读逐字稿和验收回执。
6. 蒸馏模式只使用已取得的正文或逐字稿，不从标题、简介和封面推演全文。
7. 四种结构图能在无额外第三方包时生成 SVG 和 HTML，并且节点关系可回到原文复核。
8. 解压后的整个目录通过隐私词、绝对路径、密钥字段和内部名称扫描。
9. Windows 模拟测试通过不等于真机验收；发布说明必须保留
   `beta` 和“需当前 Windows 电脑实测”的边界。
10. 用真实 PNG 或 JPEG 验收当前模型；没有真实 MP4 时，不把视频号脚本
    或 Browser 的存在写成端到端成功。
11. 用一个普通公开 X 帖子和一个公开 X Article 验收；Article 只有预览、短链、
    身份不匹配或无法取得完整正文时，必须以 `X_ARTICLE_BODY_UNAVAILABLE` 失败，
    不能生成伪完整正文。
