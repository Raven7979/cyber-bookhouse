# 内容平台说明

这里说的“支持”，意思是书屋能接住一个链接或文件，并把当前确实能读到
的内容保存下来。它不代表所有平台都能下载视频、拿到全文、字幕或逐字稿。

具体能力分为 `direct`（包内有明确路线）、`host`（需要 Agent 的可见浏览器
或文档能力）、`file`（需要用户文件）和 `metadata`（只能可靠保存元数据）。
完整边界见 [capabilities.md](capabilities.md)。

## 我们按什么顺序取内容

优先用最简单、最不打扰账号的方式：

1. 你直接提供的本地文件或平台导出文件；
2. 公开页面、官方字幕、节目简介或 RSS；
3. 你已经登录并明确授权使用的浏览器页面；
4. 如果仍然拿不到正文，就保存来源和限制，不猜内容。

不会绕过登录、验证码、付费墙、DRM、媒体令牌、访问频率或平台权限，
也不会读取浏览器 Cookie 填进笔记或日志。

## 文章和文档

| 来源 | 等级 | 通常怎么处理 | 常见情况 |
| --- | --- | --- | --- |
| 普通网页、博客、新闻页 | `direct` | 包内脚本读取公开正文 | 动态页面可能拿不全 |
| 微信公众号 | `direct` / `host` | 公开页面或授权浏览器 | 登录或反自动化可能拦截 |
| 知乎 | `direct` / `host` | 公开页面或授权浏览器 | 登录后内容、折叠内容 |
| 小红书图文 | `host` / `file` | 授权浏览器或用户导出 | 登录和动态渲染 |
| 今日头条、百家号、搜狐号 | `direct` / `host` | 公开页面或授权浏览器 | 动态渲染 |
| 微博 | `direct` / `host` | 公开页面或授权浏览器 | 登录、长线程不完整 |
| X（原 Twitter） | `direct` / `host` | 包内脚本读取公开帖子；X Article 匿名取得完整正文与原图 | 私密、删除、受限帖子和上游接口变化；长线程仍可能不完整 |
| 飞书文档 | `host` / `file` | 用户已有权限或官方导出 | 文档权限 |
| 公开 Notion | `direct` / `file` | 公开页面或官方导出 | 私有空间权限 |
| PDF、Word、Markdown、TXT、PPT | `file` | 用户提供文件 | 扫描件可能需要 OCR |

私人飞书或 Notion 文档，只处理你已经打开或主动导出的内容，不会替你
扩大分享范围。

## 视频

| 来源 | 等级 | 通常怎么处理 | 转写怎么来 |
| --- | --- | --- | --- |
| B站 | `host` / `file` | 公开信息、可见字幕或用户文件 | 可见字幕或真实本地转写 |
| YouTube | `direct` / `host` / `file` | 公开信息/字幕、可见浏览器或用户文件 | 按 [youtube.md](youtube.md) 验收每条 URL |
| 抖音 | `host` / `file` | 分享页、授权浏览器或用户文件 | 不承诺直接下载 |
| 微信视频号 | `host` / `file` / `metadata` | 已验收的腾讯元宝独立 Skill 或用户文件 | 见 [wechat-channels.md](wechat-channels.md)；只有链接时可能只保存来源 |
| 小红书视频 | `host` / `file` | 授权浏览器或用户文件 | 不用配文猜视频对白 |
| 快手 | `host` / `file` | 分享页、授权浏览器或用户文件 | 不承诺直接下载 |
| 微博视频 | `host` / `file` | 公开微博或用户文件 | 正文和视频对白分开记录 |
| X 视频 | `direct` / `host` / `file` | 包内脚本保留公开配文和媒体元数据；视频本体使用授权浏览器或用户文件 | 不承诺直接下载或转写视频本体 |
| 本地 MP4、MOV、MKV、WebM | `file` | 包内脚本取帧、探测、本地转写 | 需 FFmpeg 和本地转写工具 |

只看到标题、配文或封面时，笔记会标成 `metadata_only`。没有真正看见或
听见视频，就不会替它写内容总结。

## 播客和音频

| 来源 | 等级 | 通常怎么处理 | 转写怎么来 |
| --- | --- | --- | --- |
| 小宇宙 | `direct` / `host` / `file` | 公开节目页、简介和时间点 | 官方逐字稿、用户文件或本地转写 |
| Apple Podcasts | `direct` / `file` | 公开节目资料、发布者页面或用户文件 | 优先使用发布者逐字稿 |
| Spotify 播客 | `host` / `file` / `metadata` | 公开信息或用户文件 | 登录和媒体权限可能限制处理 |
| 公开播客 RSS | `direct` / `file` | RSS 信息和合规可访问的音频 | 保留节目和单集链接 |
| 本地 MP3、M4A、WAV、FLAC | `file` | 包内脚本本地转写 | 需本地转写工具 |

### 小宇宙会保存什么

节目页能正常打开时，至少保留：

- 单集标题、播客名称和原链接；
- 页面上确实显示的主播、嘉宾、发布时间和时长；
- 节目简介、章节和时间点。

只有在页面公开了逐字稿、你提供了音频，或当前 Agent 合规拿到音频并且
你明确要求转写时，才会生成逐字稿。音频拿不到，就保存节目资料并说明
原因，不去寻找隐藏媒体地址。

## 怎样才算处理完成

一条内容完成前要检查：

1. 原链接或原文件还在；
2. 正文、字幕和语音转写没有混成一类；
3. 逐字稿有真实来源，并写明状态；
4. Obsidian 里能正常看到文字和本地图片；
5. 哪些内容没拿到，读者一眼能看见。
